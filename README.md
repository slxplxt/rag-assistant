# Banking RAG Assistant

RAG-ассистент для ответов на вопросы по банковским тарифам. В текущей версии работает с PDF-документом Т-Банка (тарифный план ТПС 3.0).

Пользователь задаёт вопрос, система находит подходящие фрагменты документа и передаёт их GigaChat для формирования ответа. Вместе с ответом возвращаются найденные источники и номера страниц.

Проект реализован на Python с использованием LangChain, ChromaDB и FastAPI.

## Как работает

```text
PDF → извлечение текста → разбиение на чанки
    → embeddings → ChromaDB

Вопрос → поиск релевантных чанков → GigaChat
       → ответ + источники
```

Основные компоненты:

- **PyMuPDF** — извлечение текста из PDF.
- **RecursiveCharacterTextSplitter** — разбиение документа на чанки.
- **ruBERT-tiny2** — получение эмбеддингов текста.
- **ChromaDB** — хранение векторов и поиск похожих фрагментов.
- **GigaChat** — генерация ответа на основе найденного контекста.
- **FastAPI** — REST API для взаимодействия с ассистентом.

## Возможности

- Ответы на вопросы по тарифам Т-Банка.
- Поиск информации в PDF с помощью векторных представлений.
- Возврат источников с названием файла и номером страницы.
- Обработка пустых запросов и ошибок LLM.
- Возможность сообщить об отсутствии информации в документе.

В версии 1.0 используется только документ Т-Банка. Вопросы с явным упоминанием ВТБ не поддерживаются.

## Установка и запуск

Проект разрабатывался на **Python 3.12**.

### 1. Установка зависимостей

```powershell
git clone https://github.com/slxplxt/rag-assistant.git
cd rag-assistant

py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1

pip install -r requirements.txt
```

### 2. Настройка окружения

Создайте `.env` на основе примера:

```powershell
Copy-Item .env.example .env
```

Укажите в `.env` свои `GIGACHAT_CREDENTIALS`.

Проверка TLS-сертификатов включена по умолчанию. При необходимости можно указать путь к доверенному сертификату через `GIGACHAT_CA_BUNDLE`.

Для локальной разработки также предусмотрено:

```dotenv
GIGACHAT_VERIFY_SSL_CERTS=false
```

Этот вариант отключает проверку подлинности сервера и небезопасен. Не используйте его при публичном развёртывании.

### 3. Подготовка документа

Для индексации нужен PDF Т-Банка «Расчётная карта. Тарифный план ТПС 3.0 (рубли РФ)».

Его можно найти в разделе тарифных документов на официальном сайте Т-Банка. Сохраните файл по пути:

```text
data/tbank_tariff.pdf
```

Использованный в проекте документ — редакция с маркировкой `T-TPS-3.0-250116`.

PDF не хранится в репозитории. При использовании другой редакции тарифов результаты могут отличаться.

Создайте векторный индекс:

```powershell
python prepare_data.py
```

### 4. Запуск API

```powershell
python -m uvicorn main:app --reload
```

После запуска откройте Swagger UI:

**http://127.0.0.1:8000/docs**

Доступные эндпоинты:

- `GET /health` — проверка запуска сервиса.
- `POST /ask` — получение ответа на вопрос.

## Пример запроса

`POST /ask`

```json
{
  "question": "Сколько стоит обслуживание карты Т-Банка?"
}
```

Сокращённый пример ответа:

```json
{
  "answer": "При отсутствии условий бесплатного обслуживания плата составляет 99 рублей в месяц.",
  "status": "answered",
  "sources": [
    {
      "source": "tbank_tariff.pdf",
      "page": 1,
      "content": "..."
    }
  ]
}
```

Полный результат реального запуска сохранён в `evaluation/results/final_api_smoke.json`.

## Тестирование и оценка качества

В проекте есть unit-тесты, тесты API и отдельный набор вопросов для проверки RAG.

Запуск:

```powershell
python -m pytest tests/ -q
python -m evaluation.validate_dataset
```

Последний локальный запуск: **40 тестов прошли успешно**.

Для оценки retrieval подготовлен датасет из 10 вопросов: 7 с ответами в документе и 3 без необходимой информации.

| Метрика | Результат |
|---|---:|
| Evidence Recall@1 | 0.714 |
| Evidence Recall@2 | 1.000 |
| Evidence Recall@3 | 1.000 |

Это результаты на небольшом корпусе из трёх чанков. При `k=3` поиск возвращает фактически весь документ, поэтому такие значения нельзя считать полноценной оценкой качества retrieval на большом количестве документов.

Также проводилась экспериментальная оценка генерации через Ragas. Faithfulness составила 0.971 на 7 ответах, Factual Correctness — 0.824 на 5 успешно оценённых ответах. Ещё две оценки завершились ошибкой парсинга.

Эти метрики использовались для анализа ответов, а не как гарантия их правильности.

## Эксперименты и ограничения

Во время разработки я пробовал расширить корпус тарифным документом ВТБ.

Оказалось, что Dense Search плохо находил некоторые тарифные условия в длинном PDF. Я проверил очистку текста, BM25 и разные способы разбиения документа. Разбиение по тарифным пунктам улучшило положение фрагмента с нужной стоимостью с 21-го до 2-го места, но не решило проблему поиска связанных условий бесплатности.

Поэтому для первой версии я оставил один документ Т-Банка.

Основные ограничения проекта:

- Небольшой корпус и оценочный датасет.
- Качество ответов зависит от найденного контекста и GigaChat.
- Источники показывают использованные фрагменты, но не гарантируют правильность каждого утверждения.
- История диалога не учитывается.
- Проект предназначен для локальной демонстрации, а не публичного банковского сервиса.
- Полная установка в чистом окружении пока не проверена.

## Структура проекта

- `prepare_data.py` — подготовка текста и создание индекса.
- `query_data.py` — инициализация ChromaDB и GigaChat.
- `rag_service.py` — поиск контекста и генерация ответа.
- `main.py` — FastAPI.
- `schemas.py` — модели данных.
- `evaluation/` — датасет, метрики и результаты экспериментов.
- `tests/` — автоматические тесты.
